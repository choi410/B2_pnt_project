# PNT 회의록 서비스 · v4

2026-11-13 최신 B2 작업본을 팀원 PC에서 실행할 수 있도록 정리한 Git 소스 패키지입니다.
현재 사용 중인 `V3_시연용`의 화면과 기능을 포함합니다. `v4`는 전달 폴더명이며 최신 화면의 소스 경로는 `work/v3/`입니다.

## 실행 순서 · Windows

1. Git에서 내려받은 `2주차/v4` 폴더를 통째로 사용합니다. ZIP이면 먼저 압축을 풉니다.
2. **Python 3.12 64비트**를 설치합니다. Python Launcher 또는 PATH 등록을 선택합니다.
3. `01_처음한번_설치.cmd` 실행 — 최초 한 번, 인터넷 필요.
4. `02_서비스실행.cmd` 실행 — 실행 창을 열어 둡니다.
5. 브라우저에서 **http://127.0.0.1:8773/** 접속.

화면 빌드 결과를 포함했으므로 기본 실행에 Node.js는 필요하지 않습니다.
종료는 실행 창에서 `Ctrl+C`입니다. 같은 포트가 사용 중이면 해당 실행 창에서 기존 v4를 종료한 후 다시 실행합니다.
이전 V3(8771)·시연 작업본(8772)과 포트·로그인 쿠키·데이터 경로를 분리했습니다.

## 회의록 본문 검색

업무 화면 왼쪽 아래 **회의록 본문 검색** (`/search`) 에서 등록된 회의록 원문을 단어로 찾습니다.
회의록 화면 위쪽의 기존 검색창은 제목과 AI 정리 문장만 거르는 목록 필터이고, 원문 검색은 이 화면에서 합니다.

- 결과는 회의록별로 묶어 회의일, 프로젝트, 일치한 문장과 줄 번호를 보여 줍니다. 문장을 누르면 오른쪽에 원문이 열리고 그 줄로 이동합니다.
- 띄어쓰기, 대소문자, 전각·반각, 숫자의 쉼표는 구분하지 않습니다. `코팅폭` 으로 `코팅 폭`, `520mm` 로 `520 mm`, `1200만원` 으로 `1,200만원` 을 찾습니다.
- 여러 단어를 쓰면 모두 들어 있는 회의록을 찾고, 없으면 일부만 들어 있는 회의록을 알려 줍니다. `"변경 요청"` 은 붙어 있는 말만, `-보류` 는 그 단어가 있는 문장을 뺍니다.
- 프로젝트, 기간, 정렬(관련도순, 최근 회의순, 오래된 회의순)을 고를 수 있습니다.
- 한 건도 없으면 회의록에 실제로 있는 비슷한 철자를 제안합니다.
- **근거 자료 내보내기 (Word)** 는 검색어, 조건, 작성자, 회의록별 일치 문장을 한 문서로 만듭니다. AI가 고쳐 쓴 문장은 넣지 않고 원문 문장만 싣습니다.
- 같은 뜻으로 함께 찾을 단어는 `b2-service/work/v3/search_terms.json` 에 묶음으로 적습니다. 저장하면 바로 적용되고, 화면의 체크로 끌 수 있습니다.
- 참여 중인 프로젝트의 회의록만 검색되며, 휴지통의 회의록은 제외합니다.

## Supabase 로그인과 공유 데이터

`b2-service/.env` 를 설정하면 이름 선택 로그인 대신 **이메일·비밀번호 로그인(Supabase Auth)** 을 쓰고,
프로젝트·회의록·변경이력·권한을 **Supabase Postgres** 에 저장합니다. 설정하지 않으면 위의 로컬 방식 그대로입니다.

### 설정 순서

1. Supabase 에서 프로젝트를 만듭니다. 지역은 Seoul 을 권장합니다.
2. `b2-service/.env.example` 을 같은 폴더에 `.env` 로 복사하고 값을 채웁니다.

   | 값 | 위치 | 용도 |
   | --- | --- | --- |
   | `SUPABASE_URL` | Project Settings > API | 로그인 확인 |
   | `SUPABASE_ANON_KEY` | API Keys > Publishable key | 로그인 확인 |
   | `SUPABASE_DB_URL` | Connect > Session pooler | 데이터 저장 |
   | `SUPABASE_SERVICE_ROLE_KEY` | API Keys > Secret key | 선택. 관리 화면의 계정 생성·비밀번호 변경 |
   | `B2_ADMIN_EMAILS` | 직접 입력 | 관리자 이메일. 로그인할 때마다 관리자 역할로 맞춥니다 |

3. `01_처음한번_설치.cmd` 를 다시 실행합니다. 데이터베이스 연결 라이브러리(psycopg)가 추가로 설치됩니다.
4. Supabase 대시보드 Authentication > Users > Add user 에서 첫 관리자 계정을 만듭니다. Auto Confirm User 를 켜고,
   그 이메일을 `B2_ADMIN_EMAILS` 에 적습니다.
5. `02_서비스실행.cmd` 를 실행합니다. 처음 실행할 때 `b2-service/supabase/schema.sql` 의 표가 자동으로 만들어집니다.
6. http://127.0.0.1:8773/ 에서 로그인합니다. 관리자는 화면 왼쪽 아래 **사용자·권한 관리** (`/admin`) 에서 나머지 계정을 만듭니다.

### 역할과 기능

| 기능 | 담당자 | PM | 관리자 |
| --- | --- | --- | --- |
| 참여 중인 프로젝트의 회의록 등록·조회·검색 | O | O | O |
| 프로젝트 생성 | - | O | O |
| 자기 프로젝트의 PM·참여자 지정, 휴지통·영구 삭제 | 그 프로젝트의 PM | 그 프로젝트의 PM | 그 프로젝트의 PM |
| 모든 프로젝트의 PM·참여자 지정 | - | - | O |
| 사용자 추가·역할 변경·사용 중지, 역할별 기능 변경 | - | - | O |

- 역할은 `profiles.level`, 역할별 기능은 `role_permissions` 표에 저장하며 관리 화면에서 바꾸면 다음 요청부터 적용됩니다.
- 프로젝트는 참여자에게만 보입니다. 새 프로젝트는 만든 사람만 참여자로 시작하므로 PM 이 관리 화면의 **프로젝트 참여자** 에서 추가합니다.
- 사용 중지한 계정은 즉시 로그아웃되고 다시 로그인할 수 없습니다. 관리자는 항상 한 명 이상 남습니다.
- 계정을 Supabase 대시보드에서 만들어도 됩니다. 담당자로 자동 등록되며 역할은 관리 화면에서 바꿉니다.

### 알아 둘 점

- **회의록 본문과 AI 정리 결과가 Supabase(외부 클라우드)에 저장됩니다.** AI 분석은 계속 PC 에서 실행하지만 데이터는 PC 밖으로 나갑니다.
  실제 고객사 회의록은 올리지 말고 가상 데이터로 사용합니다.
- 업로드한 원본 파일(Word·PDF)과 미리보기는 등록한 PC 에만 남습니다. 다른 PC 에서는 본문·AI 정리·근거 대조는 보이지만 원본 내려받기와 페이지 미리보기는 되지 않습니다.
- 여러 PC 가 같은 데이터베이스를 쓰면 데이터가 서로 보입니다. 서버를 다시 시작해도 최근 30분 안에 시작된 다른 PC 의 AI 분석은 중단 처리하지 않습니다.
- 표에는 행 수준 보안(RLS)을 켜 두어 Publishable key 로는 읽을 수 없습니다. 데이터는 이 서버의 DB 연결로만 읽고 씁니다.
- `.env` 가 있는 상태에서도 `pytest work/v3` 는 로컬 임시 데이터만 사용합니다.

## 포함 기능

- 프로젝트별 홈, 캘린더·메모, 프로젝트 생성·휴지통.
- 여러 회의록 동시 등록, 프로젝트 연결 제안, 분석 대기·진행 상태 및 조건부 예상 시간 표시.
- 회의록 원본, AI 정리, 근거 대조, 본문 수정·재분석.
- 항목별 요구·변경 이력, 합의·요청·보류·철회 구분, 기록 수정.
- 검색·근거 기반 AI 질문, 통합 휴지통·복원·삭제, 화면 테마·글자 크기 설정.

현재 화면은 B2 중심입니다. 업무 배정·완료 검토와 D3 보고서 작성 화면은 포함하지 않습니다.
`work/v17/`은 최신 서비스가 함께 사용하는 저장소·문서·권한 등의 공통 코드이므로 삭제하면 안 됩니다.
AI 결과는 원문과 대조하고 수정할 수 있습니다. 예상 시간은 유사한 실제 처리 이력이 충분할 때만 표시됩니다.

## AI 사용 준비

**모델 파일과 가상환경은 Git에 포함하지 않습니다.** 새 회의록 AI 분석과 생성형 답변에는 아래 준비가 필요합니다.

1. NVIDIA CUDA GPU·호환 드라이버를 준비합니다. 현재 생성 모델은 BF16 지원 GPU를 사용합니다.
2. `03_선택_AI환경설치.cmd` 실행.
3. `04_선택_모델다운로드.cmd` 실행 — 수 GB 다운로드, 고정 리비전의 공개 모델 사용.
4. `05_환경점검.cmd` 실행 후 서비스를 시작합니다.

| 용도 | 모델 | 위치 |
| --- | --- | --- |
| 회의록 분석·답변 생성 | unsloth/Qwen3-4B-Instruct-2507-bnb-4bit | b2-model/models/base/ |
| 근거 의미 검색 | intfloat/multilingual-e5-small | b2-model/models/multilingual-e5-small/ |

기존에 받은 두 모델 폴더를 위 위치로 복사해도 됩니다. `.venv`는 복사하지 말고 설치 스크립트로 만듭니다.
모델이 없는 PC에서도 화면·프로젝트·파일 등록 등을 확인할 수 있으나 AI 분석은 완료되지 않습니다.
환경 점검 통과는 실제 추론 속도·가용 GPU 메모리·정확도까지 보장하지 않습니다.

## 입력 자료와 원본 미리보기

- Word `.docx`, 글자가 포함된 PDF, Excel `.xlsx`, 텍스트 `.txt`·`.md` 지원.
- Excel은 셀 텍스트를 읽습니다. 색상 막대·도형만으로 표현한 간트 기간은 해석하지 않습니다.
- 스캔 PDF·이미지 OCR은 지원하지 않습니다. 파일당 최대 8MB이며 긴 문서는 나누어 등록합니다.
- Word 원본 페이지 미리보기에는 Microsoft Word 데스크톱 프로그램이 필요합니다.
  Word가 없으면 추출한 텍스트로 확인합니다.

## 저장·Git 업로드

- 소스 업로드 대상은 **이 v4 폴더 전체**입니다. `.gitignore`, `.gitattributes`도 함께 올립니다.
- 로컬 데이터는 `b2-service/data/v4/`에 생성되며 Git에서 제외됩니다.
- `.venv`, `models`, `node_modules`, 업로드·SQLite DB·로그·비밀 설정도 제외됩니다.
- 서버 실행 중 데이터를 덮어쓰지 않습니다. 업데이트 전 필요 데이터는 별도로 백업합니다.
- 기본 실행은 자기 PC의 `127.0.0.1`에만 연결합니다. 비밀번호 없는 테스트 로그인을 인터넷 공개 배포에 그대로 사용하면 안 됩니다.
- Supabase 로그인·공유 데이터베이스는 `b2-service/.env` 를 설정했을 때만 켜집니다. 아래 **Supabase 로그인과 공유 데이터** 를 참고합니다.

## 개발

실행 진입점은 **`work.v3.server:app`**입니다. 루트 `server.py`를 직접 실행하지 않습니다.
프런트엔드를 수정할 때만 Node.js/npm이 필요합니다. `b2-service`에서 실행합니다.

```powershell
npm ci
npm run build
npm test
..\b2-model\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
..\b2-model\.venv\Scripts\python.exe -m pytest work/v3 -q
```

기능 테스트는 임시 데이터와 통제된 AI 응답을 사용합니다. 실제 모델의 정확도·속도 검증과는 별개입니다.

Supabase 로그인·권한 테스트는 비어 있는 테스트용 Postgres 가 필요하며 따로 실행합니다. 지정한 데이터베이스의 표를 지우고 다시 만들기 때문에 실제 Supabase 프로젝트는 거부합니다.

```powershell
$env:B2_TEST_DATABASE_URL='postgresql://postgres:postgres@127.0.0.1:5432/b2_test'
..\b2-model\.venv\Scripts\python.exe -m pytest work/v17/test_supabase_accounts.py -q
```
