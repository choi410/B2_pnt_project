# B2 회의록·업무 관리 v1.8.0 · CHOIN 작업본

`2주차/V2`(v1.7.2)를 바탕으로 일정 기능을 더한 **CHOIN 작업본**이며 서비스 버전은 **1.8.0**입니다.
이 폴더만으로 따로 설치·실행되고, 데이터도 상위 `V2`와 따로 저장됩니다.
회의록 등록·검토, 후속 업무 배정·처리·완료 검토, 협조 요청·답변, 알림, 변경 이력,
근거 기반 질문, 회의록 AI 정리와 프로젝트 개요를 포함합니다.
v1.8.0에서 **일정 메뉴(간트차트·일정표·변경 이력)** 와 엑셀 일정 업로드·내려받기, PNT 로고가 추가되었습니다.

> 내일 다른 컴퓨터에서 바로 실행할 때는 [다른 PC 실행 가이드](다른_PC_실행가이드.md)의 체크리스트부터 따라가세요.

## Windows에서 실행

1. 저장소를 내려받은 뒤 `2주차/V2/CHOIN` 폴더로 이동합니다.
2. **Python 3.12 64비트**를 설치합니다.
3. `01_처음한번_설치.cmd`를 실행합니다. 처음 설치할 때 인터넷이 필요합니다.
4. `02_서비스실행.cmd`를 실행하고 창을 열어 둡니다.
5. 브라우저에서 <http://127.0.0.1:8771/> 에 접속합니다.

팀원 1은 PM, 팀원 2~4는 담당자입니다. 현재 테스트 로그인은 비밀번호 없이 사용합니다.
프로젝트·회의록·업무는 비어 있는 상태에서 시작하며, 첫 실행 시 계정과 저장소가 생성됩니다.
이미 8771번 서버를 사용 중이면 `04_서버_재시작.cmd`를 실행하세요. 기존 서버를 종료하고 이 폴더의 서버를 띄웁니다.

## 같은 네트워크에서 공동 테스트

서버로 쓸 PC 한 대에서 `03_같은망_공동실행.cmd`를 실행합니다.
필요하면 같은 PC에서 `선택_공동테스트_접속허용.cmd`를 실행하고 Windows 관리자 승인을 합니다.
팀원은 실행 창에 표시되는 **Team URL**로 접속합니다. 팀원 PC마다 서버를 실행하면 서로 다른 데이터가 저장됩니다.
이 버전은 로컬·사설망 테스트용이며 비밀번호 없는 현재 구성을 인터넷에 공개 배포하는 용도는 아닙니다.

## 포함 및 제외

- 포함: Python 백엔드, React 화면 소스, 빌드된 HTML/JS, 설치·실행 스크립트, 모델 실행 코드.
- 제외: 모델 가중치, 가상환경, node_modules, 현재 프로젝트·회의록·첨부·알림·로그인 세션, 이전 버전.
- `.gitignore`는 실행 후 생성되는 데이터와 모델을 Git 추적에서 제외합니다.

`b2-model`에는 **모델 실행 코드와 설치 정보만** 있습니다. 대용량 모델 파일은 없습니다.
기본 실행은 모델을 로드하지 않습니다. 회의록 직접 정리·업무 관리 기능을 사용할 수 있으며,
새 AI 분석·AI 초안·의미 검색 및 생성형 답변에는 아래의 별도 AI 환경이 필요합니다.

## AI 환경 (선택)

NVIDIA CUDA GPU 및 호환 드라이버가 있는 PC에서 `선택_AI환경설치.cmd`를 실행합니다.
현재 개발 PC의 라이브러리 버전을 기준으로 하며 설치 다운로드 용량이 큽니다.
모델은 자동 다운로드하지 않습니다. 기존 환경의 다음 폴더를 이 패키지의 같은 위치에 복사합니다.

- `b2-model/models/base/`: Qwen3-4B-Instruct-2507 4bit 배포본.
- `b2-model/models/multilingual-e5-small/`: 근거 검색용 임베딩 모델.

생성 모델 출처와 고정 리비전은 `b2-model/model_source.json`에 있습니다.
`download_model.py`는 생성 모델만 받는 선택 도구입니다. 기본 실행·설치에서 호출하지 않습니다.
새 DOCX의 PDF 미리보기 변환에는 Microsoft Word가 필요합니다.

## 일정 (v1.8.0 신규)

좌측 **일정** 메뉴에서 프로젝트 일정을 관리합니다.

- **8단계**: 수주 → 설계 및 변경 → 구매 → 제작 → 검수 → 납품 → 현장 → 종료.
  프로젝트를 만들면 단계별 기본 마일스톤 13개(승인도 승인·핵심 부품 입고·FAT·출하·SAT는 핵심)가 자동 생성됩니다.
  착수일·납기일을 넣으면 마일스톤 예정일이 단계별로 자동 배분되고, 비우면 날짜 미정으로 생성됩니다.
- **간트차트**: 단계 요약 바 → 마일스톤(◆)·일정 항목·기한이 있는 업무를 펼쳐 봅니다. 오늘선, 지연 표시, 전체/월/주 확대.
  전체 프로젝트를 선택하면 프로젝트별 기간과 핵심 마일스톤을 비교합니다.
- **일정표**: 같은 데이터를 표로 보고 정렬·검색·완료 표시(PM).
- **변경 이력**: 항목 추가·기간 변경·진행률·삭제, 엑셀 업로드 diff, 업무의 시작일·기한 변경, 납기 변경이 시간순으로 남습니다.
- **엑셀**: `엑셀 양식`은 현재 일정이 채워진 양식(일정·프로젝트·작성 안내 시트), `엑셀 올리기`(PM)는 같은 단계·같은 항목명을 갱신하고
  나머지는 추가합니다. "엑셀 기준으로 맞추기"를 고르면 이전에 엑셀로 올린 항목 중 파일에 없는 것은 삭제됩니다.
  `엑셀 내보내기`는 일정·프로젝트·변경 이력 3개 시트를 내려받습니다. 엑셀 처리에는 `openpyxl`이 필요하므로
  기존 환경은 `01_처음한번_설치.cmd`를 다시 실행해 주세요.
- 프로젝트 생성·정보 수정에서 **프로젝트 번호·고객사·장비·호기·착수일·납기일**을 입력할 수 있습니다(양식 5종 머리말과 동일 항목).
- 샘플: `일정_샘플/` 폴더에 가상 회의록 22건 기준으로 만든 4개 프로젝트 일정 엑셀과 빈 양식이 있습니다.
  프로젝트가 없어도 전체 프로젝트 화면의 `엑셀로 프로젝트 만들기`로 올리면, 엑셀의 "프로젝트" 시트 정보로 프로젝트가 만들어집니다.

API: `GET /api/schedule[?project_id]`, `POST /api/schedule/items`, `PATCH /api/schedule/items/{id}`, `POST /api/schedule/items/{id}/delete`,
`PATCH /api/schedule/tasks/{id}/phase`, `PATCH /api/projects/{id}/info`, `POST /api/schedule/import`, `GET /api/schedule/template`, `GET /api/schedule/export`.
코드는 `work/v17/schedule.py`(백엔드)와 `work/v17/schedule.jsx`(화면)에 있습니다.

## 개발 구조

```text
b2-service/
  work/v17/          # 현재 프런트엔드 및 API (schedule.py / schedule.jsx = 일정)
  server.py         # DOCX 처리 등 공통 코드
  workflow.py       # 공통 코드 의존성
  workspace_ai.py   # 공유 AI 실행 코드
  requirements.txt
  package.json
b2-model/
  runtime.py
  download_model.py
  model_source.json
  requirements-ai.txt
portable.ps1         # 설치 및 실행 진입점
```

서비스 진입점은 **`work.v17.server:app`**입니다. 루트의 `server.py`를 서버로 실행하지 마세요.
현재 데이터베이스는 SQLite이며 AWS·Supabase 배포 구성은 이 소스에 포함되어 있지 않습니다.
데이터와 업로드 파일은 실행 후 `b2-service/data/v17/`에 저장됩니다.

화면 소스를 수정해서 다시 빌드할 때만 Node.js가 필요합니다.
`b2-service` 폴더에서 `npm ci` 후 `npm run build`를 실행합니다.
빌드 결과는 같은 폴더의 `work/v17/workspace.html`과 `app.bundle.js`에 생성됩니다.
사내망에서 npm 레지스트리가 막혀 있으면 `npm ci`가 403으로 실패할 수 있습니다. 그 경우 외부망 PC에서 빌드하거나 포함된 빌드 결과를 그대로 사용하세요.
기본 실행에는 이미 포함된 빌드 결과를 사용하므로 Node.js가 필요하지 않습니다.
