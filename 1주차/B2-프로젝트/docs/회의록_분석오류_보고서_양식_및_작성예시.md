# 작성 예시

## 1. 기본 정보

| 항목 | 내용 |
| --- | --- |
| 보고서 제목 | RP26-014 정기 협의 회의록의 조건형 기한 처리 오류 |
| 작성일 | 2026-11-05 |
| 작성자 | [작성자 입력] |
| 대상 프로젝트 | RP26-014 D사 양극 롤프레스 신규 제작 |
| 대상 문서 | RP26-014_회의록_260723_D사 정기협의#3 속도·납기 확정.docx |
| 발생 화면 | 회의록 AI 분석 |
| 실행 환경 | B2 도커 서비스 |
| 현재 상태 | 원인 확인 완료, 서비스 수정 미적용 |

## 2. 결론과 영향

Word 본문과 표는 정상적으로 읽혔습니다. 후속 조치 6번의 기한인 `GA Rev.B`를 AI가 날짜 필드에 그대로 넣으면서 검증에 실패했습니다. 서비스는 이 오류를 개별 항목으로 분리하지 않고 회의록 전체 분석 실패로 처리했습니다.

화면에는 “AI 출력 형식을 복구하지 못했습니다. 원문을 보며 직접 항목을 작성해 주세요.”라고 표시됐습니다. 이 안내만으로는 어느 항목을 확인해야 하는지 알기 어렵습니다.

## 3. 확인 결과

| 확인 항목 | 확인 결과 |
| --- | --- |
| 원본 파일 크기 | 29,631바이트, 업로드 상한 4MB 이내 |
| 본문과 표 | 본문 및 표 2개에서 텍스트 추출 확인 |
| 기본 정보 | 회의명·프로젝트명·회의일시 추출 확인 |
| 추출 본문 길이 | 2,255자, 서비스 상한 12,000자 이내 |
| 최초 모델 입력 길이 | 3,035토큰, 입력 상한 4,096토큰 이내 |
| 저장된 분석 출력 | 확인한 6건 모두 동일한 기한 값 검증 오류 발생 |
| 실패한 위치 | `items.5.due` — 후속 조치 6번의 날짜 필드 |

## 4. 원인 분석

| 구분 | 내용 |
| --- | --- |
| 조치 내용 | 집진 연결구 위치 GA 표기 |
| 담당자 | 설계 우OO |
| 원문 기한 | GA Rev.B |
| AI가 반환한 기한 | `"due": "GA Rev.B"` |
| 허용되는 기한 | `YYYY-MM-DD` 형식의 날짜 또는 미정(`null`) |
| 원인 | 문서 개정 단계를 나타내는 조건을 날짜 값으로 처리 |
| 영향 | 해당 항목의 검증 오류로 회의록 전체 분석 실패 |

`GA Rev.B`는 특정 날짜가 아니라 도면 개정 단계에 연결된 조건입니다. 자동 재시도에서도 이 값이 반복돼 해결되지 않았습니다.

## 5. 개선 방향

1. 날짜 기한과 조건형 기한을 구분합니다. `GA Rev.B`처럼 날짜가 아닌 표현은 원문 그대로 작업 조건에 보존하고, 날짜 필드는 미정으로 처리합니다.
2. 특정 항목의 값이 잘못됐을 때 나머지 결과를 보존하고, 문제가 있는 항목은 사용자 검토 대상으로 표시합니다.
3. 오류 안내에 항목명과 원문 값을 표시합니다. 예: “후속 조치 6번의 ‘GA Rev.B’는 날짜가 아닙니다. 반영 조건을 확인해 주세요.”

## 6. 검증과 현재 상태

저장된 마지막 분석 결과를 메모리에서만 복사해 다음과 같이 확인했습니다.

| 항목 | 검증에 사용한 값 |
| --- | --- |
| 날짜 기한 | 미정(`null`) |
| 조치 내용 | 집진 연결구 위치 GA 표기 (반영 조건: GA Rev.B) |
| 결과 | 항목 6개와 추가 확인 사항 2개의 형식 검증 통과 |
| 근거 번호 | 원문 행 번호 검증 통과 |
| 데이터 변경 | 저장된 회의록 및 승인 이력 변경 없음 |

이 확인은 기한 값이 전체 실패의 직접 원인임을 검증한 것입니다. 속도·납기 등 모든 결정 사항의 추출 정확도를 평가한 결과는 아닙니다.

**남은 작업:** 서비스의 조건형 기한 처리와 오류 안내를 수정한 뒤, 원본 문서를 다시 분석하고 기존 문서에 미치는 영향을 확인해야 합니다. 현재 서비스에는 해당 수정이 적용되지 않았습니다.
