## 2. 다른 PC로 옮길 항목

다른 PC에서도 현재 화면·기록·AI를 그대로 이어가려면 `B2_WebService` 폴더 전체를 복사한다. 특히 아래 항목을 빠뜨리지 않는다.

- `b2-service\src`: 프론트엔드 원본
- `b2-service\dist`: 빌드된 프론트엔드
- `b2-service\data\meetings.sqlite3`: 현재 프로젝트·회의록·업무·검토 기록
- `b2-service\server.py`, `workflow.py`, `document_formats.py`: 서버·업무 흐름·5종 문서 포맷
- `b2-model\models\base`: AI 모델, 토크나이저, 설정 파일 전체
- `01_setup.cmd`~`05_start_manual.cmd`, `manage.py`: 설치·실행·점검 도구
- 이 문서와 `00_README.txt`, `verification-status.txt`

주의사항:

- `.venv`는 이 PC에 설치된 Python 실행환경이다. FastAPI·Uvicorn 같은 웹 패키지와 PyTorch·Transformers·CUDA 관련 AI 패키지가 들어 있어 약 4.72 GiB를 차지하지만, 프로젝트 원본이나 사용자 기록은 아니다. PC별 경로와 환경이 들어가므로 전송하지 않고 새 PC에서 다시 만든다.
- 두 PC의 DB는 자동 동기화되지 않는다. 이동 직전 서버를 끈 상태에서 `meetings.sqlite3`를 복사하고, 어느 PC를 기준본으로 사용할지 하나로 정한다.
- 기존 폴더 위에 덮어쓰면 새 PC에서 만든 기록이 사라질 수 있다. 처음에는 새 폴더에 복사한다.
- AI 모델까지 옮기면 약 2.5GB 이상의 추가 공간이 필요하다. 가중치 파일만이 아니라 `base` 폴더 전체를 옮긴다.
- `b2-service\node_modules`도 전송에서 제외할 수 있다. 실행은 이미 만들어진 `b2-service\dist`를 사용하므로 Node.js가 없어도 된다. 나중에 프론트엔드 코드를 수정할 때만 `npm ci`로 다시 설치한다.
- 가상데이터 원본은 앱 폴더와 분리된 읽기 전용 기준 자료로 유지한다. 필요할 때 가져오는 import 기능을 구현한다.

### 모델 제외 전송본에서 빼도 되는 폴더

| 제외 경로 | 현재 용량 | 이유 |
|---|---:|---|
| `.venv` | 약 4.72 GiB | PC별 Python·웹·AI 설치환경이며 `01_setup.cmd`로 재생성 |
| `b2-model\models\base` | 약 2.49 GiB | Qwen AI 모델 본체; 제외하면 직접 검토 모드 사용 |
| `b2-service\node_modules` | 약 81 MiB | 프론트 개발용 패키지; 실행에는 불필요 |

세 폴더를 제외해도 소스, 빌드 화면, DB, 예시 문서, 실행 도구는 남는다. 현재 기준 핵심 전송 파일은 약 1MB이며, `b2-model` 폴더 자체는 삭제하지 말고 `models\base`만 제외한다. `b2-model\runtime.py`는 모델 유무를 판별하고 직접 검토 모드로 전환할 때 필요하다.

## 3. 새 PC 설치와 실행 순서

필수 환경은 Windows 10/11 64비트와 Python 3.12 64비트다. AI 자동 분석까지 시연하려면 NVIDIA CUDA·BF16 지원 GPU와 충분한 VRAM이 필요하다. GPU가 없어도 웹 화면과 직접 검토 기능은 사용할 수 있다.

1. `B2_WebService` 폴더 전체를 새 PC로 복사한다.
2. 복사된 `.venv`는 사용하지 않고 `01_setup.cmd`를 실행한다.
3. AI 모델을 함께 복사했다면 `03_setup_ai.cmd`를 실행한다.
4. `04_check.cmd`로 웹 구성과 GPU·모델 인식을 확인한다.
5. AI 모드: `02_start.cmd`
6. 직접 검토 모드: `05_start_manual.cmd`
7. 브라우저에서 `http://127.0.0.1:8766/`을 연다.
8. API 문서는 실행 후 `http://127.0.0.1:8766/docs`에서 확인한다.

모델 제외 전송본은 새 PC에서 Python 3.12 64비트와 인터넷 연결을 준비한 뒤 `01_setup.cmd`를 한 번 실행해야 한다. 이후 `02_start.cmd`는 모델이 없음을 감지해 직접 검토 모드로 실행한다. 기존 화면, DB 조회, 직접 항목 등록·검토·저장·CSV 출력은 사용할 수 있지만 새 AI 자동 분석은 사용할 수 없다. AI가 필요해지면 `b2-model\models\base` 전체를 추가하고 `03_setup_ai.cmd`와 `04_check.cmd`를 차례로 실행한다.

개발 검증 명령:

```powershell
cd B2_WebService
.\.venv\Scripts\python.exe manage.py verify
cd .\b2-service
..\.venv\Scripts\python.exe -m pytest -q
npm ci
npm run build
```

AI 조건까지 점검할 때:

```powershell
cd B2_WebService
.\.venv\Scripts\python.exe manage.py check --require-ai
```

## 7. 더 필요한 가상데이터

현재 패키지는 “회의록에서 요구사항과 변경을 찾는 기능”에는 충분하다. 다만 5종 문서를 자동 작성하고 문서 간 오류를 찾는 단계까지 가려면 아래 데이터가 추가로 필요하다.

### 반드시 추가할 데이터

1. **완성된 5종 문서 한 세트**  
   PNT-SIM-001의 최종 요구사항을 실제로 채운 정답 문서 5개가 필요하다. 빈 양식만으로는 AI가 올바르게 채웠는지 평가할 수 없다.
2. **문서 필드별 정답표**  
   `문서종류, 필드ID, 기대값, 단위, 근거 요구사항번호, 근거 회의번호, 필수여부`를 CSV로 만든다.
3. **문서 개정 이력**  
   문서번호, Rev, 작성자, 검토자, 승인자, 상태, 작성일, 승인일, 변경 사유가 필요하다.
4. **문서 간 불일치 사례**  
   설계 사양과 작업지시가 다름, 미승인 변경이 제작에 반영됨, 구버전 도면 사용, 검사 항목 누락 같은 의도적인 오류 데이터를 만든다.
5. **제작·검사 결과 데이터**  
   작업지시 번호, 장비 번호, 실측값, 단위, 허용범위, 합격/불합격, 재검 결과, 조치자를 포함한다.
6. **요구사항의 세부 구조 정답**  
   현재 앱 스키마보다 자세한 `이전값, 신규값, 단위, 허용오차, 기준 위치, 대상 장비, 제외 장비, 변경 유형, 적용 상태`가 필요하다.
7. **권한 테스트 계정**  
   실제 로그인을 구현할 경우 PM, 설계, 제작, 품질, 고객 역할별 가상 계정과 프로젝트 접근 권한이 필요하다.

### 있으면 좋은 데이터

- 빈 필드, 중복 요구사항, 잘못된 날짜, 단위 누락, 모순 문장 같은 경계 사례
- OCR이 필요한 스캔 문서, 표가 깨진 문서, 한글·영문 혼합 문서
- 가상 도면과 사진, 첨부파일 메타데이터. 첨부 분석 기능을 실제로 만들 때만 추가한다.
- 프로젝트 3~5개, 프로젝트당 회의 10개 이상 규모의 반복 데이터
- 완료된 정상 프로젝트와 중간에 취소·보류된 프로젝트 비교 데이터

## 8. 아직 구현되지 않았거나 제한된 부분

- 현재 역할 선택은 체험용이며 실제 로그인·비밀번호·권한 검증이 아니다.
- 5종 문서 화면은 현재 구조를 보는 카탈로그다. 문서 생성·저장·AI 자동 채움·DOCX 출력은 아직 없다.
- PNT CSV/Excel 패키지를 앱 DB로 가져오는 전용 import 기능이 없다.
- 현재 AI 결과 스키마는 분류, 내용, 담당자, 기한, 합의 상태, 근거 중심이다. 요구사항 버전 관리와 장비별 적용을 위해 스키마 확장이 필요하다.
- DOCX의 첨부 이미지·도면·스캔 OCR 분석은 없다.
- 알림, 클라우드 동기화, 여러 사용자의 동시 편집은 없다.
- 회의 입력에서 프로젝트와 날짜 일부가 자유 입력이라 마스터 데이터 선택 UI가 필요하다.
- 정답표를 이용해 precision/recall/F1과 필드 정확도를 계산하는 자동 평가 실행기가 없다.

## 9. 다음 작업 권장 순서

1. PNT 패키지를 별도 테이블로 읽어 들이는 import/초기화 도구 구현
2. 요구사항 현재값·이력·대상 장비 스키마와 화면 추가
3. PNT-SIM-001의 5개 DOCX를 순서대로 처리하는 시연 시나리오 연결
4. 추출 정답·비추출 정답 기반 자동 평가 실행기와 결과 리포트 추가
5. 5종 완성 정답 문서와 필드별 정답표 제작
6. 5종 문서 AI 제안·사람 검토·저장·DOCX 출력 구현
7. PNT-SIM-013으로 최종 블라인드 평가
8. 실제 운영 범위가 확정되면 로그인·권한·다중 사용자 기능 구현

가장 먼저 할 일은 기능을 더 넓히는 것이 아니라, **PNT-SIM-001 한 프로젝트가 회의 1~5차를 거치며 요구사항 현재값과 변경 이력이 정확히 누적되고, 그 확정값으로 5종 문서가 작성되는 한 줄의 시연 흐름**을 완성하는 것이다.
