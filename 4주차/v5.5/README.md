# PNT 회의록 서비스 v5.5 보관본

2026-11-23 현재 서비스의 소스, 화면 빌드, 모델 실행 코드와 가상 예제 자료를 모은 Windows용 패키지입니다. 배포 버전은 **6.0.0**입니다.

`v5.5`는 최초 업로드 원본을 별도로 보관하기 위한 폴더 이름입니다. 프로그램 내부 버전 `6.0.0`, 포트 `8777`, 데이터 경로 `data/v6`는 원본 설정을 유지합니다. `v6` 작업본과 같은 포트를 사용하므로 한 번에 하나씩 실행합니다.

## 다른 컴퓨터에서 실행

1. **v5.5 폴더 전체**를 내려받고, ZIP이면 압축을 풉니다.
2. **Python 3.12 64비트**를 설치합니다. Python Launcher와 PATH 등록을 선택합니다.
3. **01_처음한번_설치.cmd**를 실행합니다. 처음 설치할 때 인터넷이 필요합니다.
4. **02_서비스실행.cmd**를 실행합니다. 브라우저가 열리면 이름을 선택해 로그인합니다.
5. 접속 주소는 **http://127.0.0.1:8777/** 입니다.

실행 창을 열어 두고 사용합니다. 종료하려면 해당 창에서 `Ctrl+C`를 누릅니다.
화면 빌드가 포함되어 있으므로 사용만 할 때는 Node.js가 필요하지 않습니다.
Python 가상환경은 컴퓨터마다 새로 설치해야 합니다.

기존 서비스(8775), v5(8776)와 포트·데이터 폴더·로그인 쿠키를 분리했습니다.
v5 데이터를 자동으로 가져오거나 덮어쓰지 않습니다.

## 포함한 변경

- 홈 프로젝트 카드를 작게 정렬하고 현재 진행단계를 강조합니다.
- 상단 변경이력 옆에서 프로젝트를 선택하고, 선택한 프로젝트 코드를 확인합니다.
- 홈 프로젝트 카드는 해당 프로젝트 흐름을 열고, 상단 변경이력은 변경 기록을 바로 엽니다.
- 변경이력 항목 목록·상태·상세조건·분류 편집 및 검색 구성을 반영했습니다.
- AI 대화의 질문 해석, 프로젝트 정보 조회, 변경 기록 집계, 후속 질문 처리 개선을 포함합니다.
- 앞 답변에 프로젝트가 여러 개 있을 때 "이 프로젝트만"이라는 후속 질문은 대상을 먼저 확인합니다.
- 적용일과 등록 시각이 같은 납기 기록은 근거 회의일을 함께 비교해 최신 합의 일정을 표시합니다.
- 회의록 등록·분석·검토, 요구사항 표, 근거 원문, 캘린더, 검수·승인·메일 기능을 유지합니다.

Thinking 모델 교체, 추가 학습, PostgreSQL/pgvector 전환, AWS 배포는 아직 적용하지 않았습니다.
현재 구현은 Qwen Instruct 모델과 E5 검색을 사용하며, 검색 벡터는 기존 DB에 저장합니다.

## AI 분석·대화 준비

기본 설치만으로 예제와 화면을 확인할 수 있습니다. 새 회의록의 AI 분석과 의미 검색·생성형 답변에는 다음 준비가 필요합니다.

1. 호환되는 NVIDIA CUDA GPU와 드라이버를 준비합니다. 포함된 기본 실행 엔진은 CUDA 및 BF16 지원을 확인합니다.
2. **03_AI환경설치.cmd**를 실행합니다.
3. **04_모델다운로드.cmd**를 실행합니다.
4. **05_환경점검.cmd**에서 기본 서비스와 AI 준비 상태를 확인합니다.
5. 서비스를 종료한 뒤 **02_서비스실행.cmd**로 다시 실행합니다.

| 용도 | 모델 | 다운로드 위치 |
| --- | --- | --- |
| 회의록 분석·답변·질문 해석 | unsloth/Qwen3-4B-Instruct-2507-bnb-4bit | 프로그램/b2-model/models/base |
| 의미 검색 | intfloat/multilingual-e5-small | 프로그램/b2-model/models/multilingual-e5-small |

다운로드 스크립트는 고정 리비전을 사용합니다. 모델 출처와 라이선스 정보는 다운로드 자료 및 `model_source.json`을 확인합니다.
모델 가중치·Python 실행 환경·설치 라이브러리는 Git에 포함하지 않습니다. 이미 받은 동일한 모델 폴더는 복사해 사용할 수 있습니다.
다운로드는 공개 모델을 받는 과정이며 회의록을 외부로 보내는 작업이 아닙니다.

기본 실행은 다른 프로그램이 사용하는 8080 AI 서버에 자동 연결하지 않고 포함된 로컬 모델 설정을 사용합니다.
GPU 없는 컴퓨터에서 현재 생성 모델이 동일한 속도로 실행되는 구성은 아닙니다.
환경 점검 통과는 실제 추론 성공·응답 속도 보장을 뜻하지 않습니다. 각 PC의 GPU 메모리와 실제 질문으로 확인해야 합니다.

- 각 PC의 데이터는 독립적입니다. Git으로 코드를 받아도 이후 등록한 회의록이 다른 PC와 동기화되지는 않습니다.
- 작업 자료를 백업·이동할 때는 서버를 종료하고 `data/v6` 폴더 전체를 복사합니다. 원문이 있는 `files` 폴더도 필요합니다.
- 이 패키지는 이름 선택 로그인과 localhost 접속을 사용하는 로컬 검토용입니다. AWS 운영 배포를 완료한 패키지가 아닙니다.

## 메일 설정

기본값은 실제 발송하지 않는 `console` 모드입니다. 발신 계정 비밀정보는 포함하지 않습니다.

1. `프로그램/b2-service/.env.example`을 같은 폴더의 `.env`로 복사합니다.
2. 사용 중인 메일 서비스의 SMTP 설정을 확인하고 `.env`에 입력합니다.
3. `MAIL_MODE=smtp`로 설정하고 서비스를 재시작합니다.

예제 파일에는 네이버 SMTP 항목과 공식 안내 링크가 있습니다. 각 PC에서 발신 계정을 별도로 설정합니다.
자기 컴퓨터의 localhost 승인 링크는 외부 고객이 접속할 수 없습니다. 실제 외부 발송에는 접속 가능한 서버 주소 설정이 필요합니다.

## 문제 해결

- Python을 찾지 못하면 Python 3.12 64비트 설치를 확인합니다.
- 설치가 중단되면 01을 다시 실행하고 오류를 확인합니다.
- 8777 포트 사용 중이면 이미 실행한 v6 창을 확인합니다.
- 원문이 안 열리면 폴더 전체와 `data/v6/files`가 함께 있는지 확인합니다.
- AI가 동작하지 않으면 03·04 완료 여부와 05의 GPU·모델 상태를 확인합니다.
- DOCX 원본 페이지 미리보기에는 Windows용 Microsoft Word가 필요합니다. 포함한 예제는 PDF이므로 Word 없이 볼 수 있습니다.

Python 경로를 직접 지정해야 한다면 v5.5 폴더에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\프로그램\portable.ps1 -Mode Setup -Python "D:\Python312\python.exe"
```

## 개발·검증

실행 진입점은 `work.v3.server:app`입니다. `work/v3`와 `work/v17`은 내부 모듈 경로이며 패키지 버전과 다릅니다.
화면 소스를 고칠 때 Node.js/npm을 설치한 뒤 `프로그램/b2-service`에서 실행합니다.

```powershell
npm ci
npm run build
npm test
..\b2-model\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
..\b2-model\.venv\Scripts\python.exe -m pytest work/v3 -q
```

자동 검사는 임시 데이터 및 통제된 모델 응답을 사용하는 부분을 포함합니다. 실제 모델의 품질·속도 평가와 구분합니다.
검증 결과는 `검증결과.txt`에 기록합니다.
